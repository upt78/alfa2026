# Тестовые сценарии

Все данные синтетические. Перед ручными проверками выполните `docker compose up --build` и откройте http://localhost:8001.

| ID | Сценарий | Шаги / данные | Ожидаемый результат |
|---|---|---|---|
| E2E-01 | Персональный подбор | ИНН `7701234567`; 1 млн ₽; 24 мес; оборотные средства | До 3 предложений; первый имеет максимальный `match_score`; показано объяснение |
| E2E-02 | Успешный кредитный путь | Создать заявку на 2 млн ₽, 24 мес для ООО Ромашка | Статусы последовательно доходят до `signing`; после подписания `issued`; есть ставка и история |
| E2E-03 | Сохранение | После E2E-02 обновить страницу и перезапустить app | Заявка доступна по ИНН, история не потеряна |
| E2E-04 | Отказ на внешней проверке | ИНН `7707654321`, ООО Лютик | Статус `rejected`, причина — ликвидация/отсутствие в реестре |
| E2E-05 | Уточнение | Для заявки в `clarification` ввести комментарий и отправить | Статус `external_check`, комментарий добавлен в историю |
| API-06 | Валидация | ИНН `abc` или пустая цель | HTTP `422`, заявка не создаётся |
| API-07 | Несуществующие сущности | `product_id=999` или заявка `id=999999` | HTTP `404` с понятным сообщением |
| API-08 | Неверный переход | Подписать заявку не в `signing` | HTTP `409`, состояние не меняется |
| UI-09 | Каталог и сравнение | Открыть «Кредиты», фильтры и сравнение 2–3 продуктов | Данные приходят из `/products`, сравнение использует те же лимиты и ставки |
| OPS-10 | Готовность контейнеров | `docker compose ps`, `curl http://localhost:8001/health` | Оба контейнера healthy, API возвращает `status=ok` |

## Автоматические проверки

- `pytest -q` — изолированная SQLite БД, worker выключен, переходы вызываются детерминированно.
- `npm run lint && npm run build` — TypeScript, ESLint и production-сборка.
- `python3 scripts/e2e_smoke.py` — реальный HTTP против запущенного Docker-стека: health → каталог → рекомендации → заявка → ожидание `signing` → подписание → проверка сохранения.

Smoke-тест создаёт синтетическую заявку в текущей БД. Для чистого повтора можно выполнить `docker compose down -v`, понимая, что это удалит все демонстрационные заявки.
